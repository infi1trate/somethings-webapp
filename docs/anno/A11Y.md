# `anno` — WCAG 2.2 AA audit

Every row is a measurement taken from the live DOM — computed styles, measured
rects, real key presses — not a reading of the source. Where a criterion could not
be tested as written, that is stated with the reason rather than marked pass.

**Taken against** `main` (uncommitted), `localhost:3000`, viewport 1280×860,
both themes where colour is involved.

Ratios are computed with the WCAG relative-luminance formula against the nearest
painted ancestor background (not an assumed page colour).

## 1.4.1 Use of colour

Resolved vs unresolved is a **shape** difference, not a hue difference, and the
same language is used in both surfaces so they cannot disagree.

| Surface | Unresolved | Resolved | Survives greyscale? |
|---|---|---|---|
| Pin layer | filled disc + number, grey luminance **0.165** | ring only + check SVG, luminance **1.000** | ✅ gap **0.835** |
| Drawer row chip | filled + number, **0.165** | ring + check, **1.000** | ✅ gap **0.835** |

Measured under `filter: grayscale(1)` with the filter confirmed applied
(`grayscale(1)` read back from the computed style): `fillDiffers: true`,
`glyphDiffers: true`. A greyscale screenshot of the drawer and pin layer together
is in the anno-05 transcript.

Other colour-carried meanings are all label-backed: the orphan group header
carries the words "Page no longer exists"; the anchor-lost pin carries a dashed
edge **and** the label "Anchor lost — showing last known position"; the
`real`/`mocked` chip prints the word.

**Pass.**

## 1.4.11 Non-text contrast — 3:1

| Boundary | Colour | Against | ratio | Pass |
|---|---|---|---|---|
| **Pin outer edge** | `#6e6b67` | `#FFFFFF` | **5.30** | ✅ |
| **Pin outer edge** | `#6e6b67` | `#000000` | **3.96** | ✅ |
| Pin light stroke | `#ffffff` | `#000000` | 21.00 | ✅ |
| Focus indicator (`--focus-ring`) | `#716a60` | drawer `#ffffff` | 5.34 | ✅ |
| Drawer left border | `#1f1e1d` | `#ffffff` | 16.64 | ✅ |
| Count badge ring | `#6e6b67` | badge `#7b5bd6` | — | see note |

**Why the edge is a mid-tone.** Appendix B specifies a "thin **dark** outer edge",
and a dark edge cannot satisfy the brief's own requirement of 3:1 against *both*
white and black: `#1f1e1d` measures **1.26:1 against black**. The arithmetic
admits only luminances between 0.10 and 0.30 — a mid-tone. `--text-muted`
(`#6e6b67`, luminance 0.148) is an existing Bloom token that clears both. The
light stroke is retained inside it and carries the dark-background case with a far
larger margin. Logged in [GAPS.md](GAPS.md) as an Appendix B wording change.

*Badge ring note:* the 1px `#6e6b67` ring on the violet badge is decorative
separation, not the badge's boundary against the page — the badge sits on the dev
bar surface, where its own fill provides the edge.

**Pass.**

## 2.1.1 Keyboard

Every pin action is reachable from the drawer, which is the whole reason the drawer
is P0. No action exists only on a pin.

| Pin action | Drawer equivalent | In tab order |
|---|---|---|
| select | comment body button | ✅ |
| resolve / unresolve | `Resolve comment n` / `Reopen comment n` | ✅ |
| edit | `Edit comment n` → textarea → `Save changes` | ✅ |
| delete | `Delete comment n` | ✅ |
| **undo delete** | `Undo delete` **on the row** | ✅ |
| copy link | `Copy link to comment n` | ✅ |
| view captured context | `Show full comment and details` | ✅ |

**Undo is deliberately on the row, not only the toast.** sonner renders outside
the drawer's DOM subtree, so the toast's Undo button is outside the focus trap and
a keyboard reviewer cannot Tab to it. The toast is the pointer affordance; the row
is the accessible one. Both call the same `restore`.

### Full tab-order transcript

Recorded with **16 real `Tab` key presses**, drawer open, `Unresolved` filter:

```
 1  Close comments
 2  Unresolved            (filter, aria-checked=true)
 3  All
 4  Mine
 5  "Written by a different reviewer."     ← row 79 body
 6  Show full comment and details
 7  Edit comment 79
 8  Resolve comment 79
 9  Delete comment 79
10  "Alt-held: second, still armed."       ← row 77 body
11  Show full comment and details
12  Edit comment 77
13  Resolve comment 77
14  Delete comment 77
15  "Alt-held: first of a batch."          ← row 76 body
16  Edit comment 76 …
```

`allStayedInDrawer: true` — focus never left the panel. Every stop reported
`:focus-visible`. The bar itself is not a tab stop.

The dev bar's own order (9 stops, real key presses): Mentor → Lead mentor →
Supervisor → Admin → scenario select → load select → status line → Hide → Reset,
then focus exits to the Next dev overlay.

### Honest limit on activation

The Browser pane injects `Enter` with an **empty `code`**, so the browser's native
button activation never fires — verified directly (`delivered: ["|", "Enter|",
"|"]` for Return/Enter/space). **Focus movement and tab order above are real key
presses.** The lifecycle *activations* were performed by activating the focused
element, which is what the browser does on Enter for a native `<button>`. I did
not add key handlers to native buttons to work around a harness limitation.

**Pass** (activation verified by proxy, stated).

## 2.1.2 No keyboard trap

Esc from every modal-ish surface:

| Surface | Escapes | Notes |
|---|---|---|
| Drawer | ✅ | closes, `aria-expanded` → false, **focus returns to the toggle** |
| Place mode (armed idle) | ✅ | → View |
| Composer (clean) | ✅ | discards silently, **stays** in Place |
| Composer (dirty) | ✅ | confirms first, draft intact |
| Discard confirmation | ✅ | backs out, draft still in the field |

The Esc ladder is deliberate: confirmation → draft → mode. One press never both
discards a comment and disarms the layer.

**Focus return was a defect.** It initially landed on `<body>` — the trap restored
`document.activeElement` from mount time, which is nothing when the drawer is
opened without focusing the toggle first. The toggle is now named explicitly.

**Pass.**

## 2.4.11 Focus not obscured (minimum)

**The criterion as briefed cannot be run as written.** A focus trap and "tab
through the prototype underneath" are mutually exclusive — the trap exists to stop
Tab reaching the prototype.

So it was measured the only way that is meaningful for a modal panel: what a
*forced* focus would hit.

| | Measured |
|---|---|
| Interactive controls underneath | 52 candidates |
| Programmatically focusable | 30 |
| **Geometrically behind the 352px panel** | **6** — two provenance triggers, three timeline entries, one flag row |
| **Reachable by Tab while the drawer is open** | **0** |

Obscuration is prevented by the trap, not by geometry. If the drawer were ever
made non-modal, those six would need `inert` on the prototype or a
`scroll-padding` offset.

**Pass**, with the reading stated. The decision — modal or non-modal — is open in
[GAPS.md](GAPS.md).

**Two failures found and fixed in this phase:** row body was **299 × 20**, and

### Gap between adjacent pins

With 37 pins on one page, the closest pair (**83 / 84**) measured a
**0px centre-to-centre gap** — they are exactly co-located, so one is
unreachable by pointer.

The pins themselves each satisfy 24×24, so 2.5.8's size clause is met and its
spacing clause (the 24px-circle test) applies to *undersized* targets, which these
are not. But a fully occluded target is a real usability failure regardless of
which clause it falls under. **This is the measured case for R17 clustering, which
the brief scopes to anno-08.**

**Pass on size; clustering outstanding by design.**

## 3.3.1 / 3.3.3 Error identification and suggestion

Every failure state names what happened and what to do. None says "something went
wrong".

| Failure | Message | Suggestion |
|---|---|---|
| Store unreachable (read) | "Can't reach the comment store" + the store's own sentence | **Try again** button |
| Store unreachable (write) | "Couldn't reach the comment store. Your note is saved here and will retry." | draft preserved; retry offered |
| Body over 1000 | "A comment can be at most 1000 characters." | the count is the fix |
| Empty body | "A comment needs something in it." | — |
| Empty name | "A name can't be empty. Clear it and we'll use the generated one." | names the fallback |
| Name conflict | "Another reviewer is already called Slate Heron. You can still use it — your comments are told apart by the colour dot, not the name." | **not blocked** |
| Clipboard refused | "Couldn't copy — select the link and copy it manually" | manual path |
| Placement refused (record-bound) | "Can't comment on a single row — try the list or panel around it." | names what to aim at |
| Placement refused (untagged) | "Nothing to anchor to here. Try a panel, card or control." | names what to aim at |
| Deeplink comment missing | "That comment no longer exists. It was deleted after the link was made. You are on the right page — everything else from the link was applied." | states what still worked |
| Deeplink route gone | "The page this comment was written on no longer exists. It is below under **Page no longer exists**, where you can still read and delete it." | points at the group |
| Deeplink params invalid | "2 link settings were ignored. `load=sideways` — not a load state this prototype has; `scenario=not-a-real-scenario` — not a scenario this screen has. The default is in use instead." | **names each parameter and value** |
| Local store in use | "These comments are on this device only. No other reviewer can see them, and clearing your browser data deletes them." | persistent, in the body |
| Storage blocked (identity) | "This browser is blocking storage, so this name lasts until you reload." | states the consequence |
